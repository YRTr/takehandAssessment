Problem Statement: Real-time AI Inference Dashboard & Worker

You must architect a decoupled full-stack application that simulates a high-throughput AI text-to-video generation pipeline. The system must not lock up the client during processing.

Technical Requirements:

  • Frontend (React/MERN): A dashboard where users submit a text prompt. The UI must show real-time status updates (Queued -> Processing -> Completed) without manual page reloads.
  • Backend (Node.js/Express): Accepts the prompt, authenticates the user, and pushes the job to a message queue.
  • Cloud (AWS): Utilize AWS SQS to queue the prompts. Use AWS S3 to store the final generated output (simulate a mock video file or JSON payload upload).
  • Worker Node (Python): Write a standalone Python daemon that continuously polls the AWS SQS queue. Upon receiving a message, simulate a 10-second processing delay (mocking the AI workflow), generate a dummy file, upload it to S3, and update a MongoDB database with the finished status.

Hints & Guidelines

  • Focus heavily on the Python `boto3` library for SQS polling and S3 uploads.
  • Ensure environment variables (`.env`) are used strictly across both Node and Python environments. Never hardcode AWS keys.
  • Consider how the React frontend knows the Python worker finished. WebSockets (Socket.io) attached to MongoDB change streams or short-polling are acceptable.
